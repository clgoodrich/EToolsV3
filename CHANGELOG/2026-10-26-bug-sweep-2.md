# Bug sweep 2: parsers, survey math, Casing Review, UI state

- **Date:** 2026-10-26
- **Author:** Colton Goodrich (with Claude Code)
- **Commit(s):** see `git log --grep "bug sweep 2"`

## What changed
A second audit of the whole app. Every fix below was first reproduced by a
script against real fixture PDFs or the real app code, then re-run after the
fix to confirm it.

**PDF parsing**
- WCR Section 32 formation tops: 294 of the 294 printed tops across the 63
  test WCRs now parse, up from 13. Rows with a blank description, blank TVD,
  "Oil/Gas" or a 3-digit spaced depth ("3 8 8") used to be dropped.
- WCR Section 33 intervals with blank TVD cells, or a spaced FR ("1 0"),
  now give the perf interval, so Frac_Start / Frac_End rows are written.
- WCR Section 27 and APD location rows accept a plain quarter ("NE") or
  "LT12" as the QQ.
- APD "Geologic Formation Tops" side-column layout (Crescent Point) is read
  by position. All 9 tops are now correct; before, an invented "Uteland Butte
  5224/8084" row appeared.
- APD: upper-case string tags (COND/SURF/PROD) and an "API Well Number:"
  stamp are read.
- Survey text reader:
  - MDs with thousands separators ("1,500.00") no longer truncate the survey.
  - A stray block of anti-collision rows past TD (MD 47,164 – 55,550) is
    dropped.
- DDR time logs: each job's log starts at its own "Job Category" line. The
  Completion log no longer repeats the Drilling log's last rows.
- DDR events read comma depths under 10,000 ft ("8,181'") and
  "** KOP** SLIDE 9,641'".

**Survey math**
- Magnetic declination passed the altitude to pygeomag in metres instead of
  km, so a magnetic-north survey was rotated about 2.7° (about 500 ft at a
  10k ft lateral's BHL).
- `detect_kop` no longer invents a KOP for a hole that never passes 5°.
- UTM is always zone 12, matching the plat DB. Utah's western strip got
  zone-11 eastings and found no sections.
- Processed azimuths are wrapped to [0, 360).
- The WCR casing table keeps 3 decimals (9.625, not 9.62).
- Pasted CSV rows with 3-digit azimuths ("1000,1.5,245.3") are no longer
  dropped.

**Casing Review**
- **String TVDs come from the survey again.** `welltrack_from_dataframe` needed
  a TVD column, which only the old DB surveys had. The PDF plan and typed
  surveys (MD / Inc / Azi) were dropped silently, so since the PDF-only
  change every design used the straight-hole estimate behind a "Survey: …"
  chip. TVD is now computed by minimum curvature. On the Myton City 7H the
  intermediate TVD goes from 7650 to 8238, and surface from 1900 to 1894.2.
  That matches the hand-made review (B34 = 8237.92, B19 = 1894.19).
- The DataPrint sheet is left to its template formulas. The writer used to put
  results in the MW/grade/cement row, one column left, overwriting the
  formulas there and the B7 label.
- An intermediate liner no longer jumps to the STRING 4 block ahead of a
  deeper production string, which had reversed the next/previous-shoe links.
  The last string still goes in STRING 4.
- The wellbore diagram draws a liner and its cement from the liner top, not
  from the surface.
- BOPE "Max Pressure Allowed @ Previous Casing Shoe" includes the previous
  string's internal yield, like sheet cell C31 (K20 = `=C10`).
- Section segment edits:
  - a bearing changed to 0°, or a change to only the quadrant, is kept;
  - an edit to bearings only no longer reshapes the section polygon.
- BHL Section 4–7 copies keep BHL 3's conditional formats and print area.

**UI state**
- Casing Review: frac gradient and the Output card reset per well. Before,
  well B was generated with well A's frac.
- WCR tab: the Output card resets per well.
- A survey PDF uploaded on the WCR tab survives a well switch or reconnect.
- Uploading an APD/WCR without parsing no longer wipes the active well's
  parsed data; the file is staged until Parse succeeds.
- PDFs with no readable API get their own workspace buffer, keyed by file
  name. Before, all of them shared `0000000000` and inherited each other's
  edits.
- "Use as active well" no longer reports success after the pipeline failed,
  so the fallback refresh runs.
- Map & Viz clears the previous well's 3-D trajectory and click readout.
- With two browser tabs open, a load refreshes both. Before, only the last
  tab opened was refreshed.
- WCR Generate runs off the event loop.

## Notes / follow-ups
- Magnetic declination still uses today's date, not the survey date. This
  only matters for magnetic-north surveys: about 28 ft at the BHL for a
  2025 survey.
- `_trim_outlier_endpoints` still drops end stations beyond a 1,500 ft gap,
  which would cut a very sparse plan (stations 2,500 ft apart). That is
  existing behaviour and was not changed.
